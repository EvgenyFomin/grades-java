# 4. Система привилегий в Linux

## Базовая модель прав: владелец и группы

Каждый файл и директория в Linux принадлежат **пользователю-владельцу** (owner) и **группе** (group). Права задаются отдельно для трёх категорий:

| Категория | Символы | Кто |
| --- | --- | --- |
| Владелец | `u` (user) | пользователь, которому принадлежит файл |
| Группа | `g` (group) | все пользователи группы файла |
| Остальные | `o` (other) | все остальные |

Каждая категория может иметь три права:

| Право | Символ | Значение для файла | Значение для директории |
| --- | --- | --- | --- |
| Чтение | `r` (read) | прочитать содержимое | **увидеть список имён** файлов в директории |
| Запись | `w` (write) | изменить содержимое | **создавать/удалять/переименовывать** файлы внутри |
| Выполнение | `x` (execute) | запустить файл как программу | **войти в директорию** и обращаться к файлам внутри |

В `ls -l` права выглядят как 10 символов: тип файла + 3×3 права:

```
-rwxr-xr-- 1 user dev 1234 aug 16 09:00 script.sh
│ ──┬── ─┬── ─┬──
│  u    g   o
```

- `user`: `rwx` — может читать, писать и запускать.
- `dev` (группа): `r-x` — может читать и запускать, но не менять.
- `other`: `r--` — только читать.

Важный момент для понимания I/O: права на **директорию** и на **файл** — разные вещи. Чтобы открыть `/data/notes.txt`, нужен `x` на `/data` (войти) и `r` на сам файл. А чтобы удалить файл — достаточно `w` на **директории**, права самого файла не важны.

Нюанс: **`w` на директории сам по себе ничего не даёт.** Он работает только вместе с `x`: чтобы создать, удалить или переименовать файл внутри директории, ядро всё равно требует `w` + `x` (право на вход). Если у пользователя есть `w` без `x` (например, `-w-`), формально запись разрешена, но войти в директорию он не может, поэтому реально сделать ничего нельзя — ядро откажет в операции. На практике `w` на директории имеет смысл только в связке `wx`.

## Проверку прав делает ядро

Проверка прав — не задача приложения. На каждом `open()`, `read()`, `write()`, `stat()` ядро (в kernel mode, см. п. 3) сверяет реальные и эффективные UID/GID процесса с правами файла. При несовпадении возвращается ошибка `Permission denied` (errno 13). Приложение не может её обойти, потому что решение принимает ядро, а не оно.

## setuid / setgid — что такое `rws`

Обычная программа запускается с правами пользователя, который её запустил. Но некоторым программам нужны **повышенные права** для одной операции. Пример — `/usr/bin/passwd`: менять свой пароль можно любому пользователю, но запись в `/etc/shadow` доступна только root. Решение — бит **setuid** (Set User ID): он говорит ядру «при запуске этого файла дай процессу права **владельца файла**, а не запускающего пользователя».

В `ls -l` это выглядит как `s` на месте `x` у владельца:

```
-rwsr-xr-x 1 root root 64152 aug 16 09:00 /usr/bin/passwd
 │  │
 тип  setuid: выполняется с правами владельца (root)
```

- `rws` = `rw` + setuid. Для владельца права `rwx`, но `x` «заменён» на `s` (executable + setuid).
- Если права владельца **без** `x`, бит отображается заглавной **`S`** — это setuid, который не сработает (нечего «выполнять»).

Аналогично есть **setgid** (Set Group ID) — `s` на месте `x` у группы, выполняется с правами группы файла:

```
-rwxr-sr-x 1 root shadow 64152 aug 16 09:00 /usr/bin/xxx
     │
   setgid
```

Для **директорий** setgid работает иначе: новые файлы, созданные внутри, наследуют группу директории, а не группу создателя.

## sticky bit — что такое `rwt`

Бит **sticky** (в Linux «restricted deletion flag») устанавливается на директории. Его символ — `t` на месте `x` для категории «остальные»:

```
drwxrwxrwt 1 root root 4096 aug 16 09:00 /tmp
 │       │
 тип    sticky bit (t)
```

Что он делает: в директории со sticky bit **файл может удалить или переименовать только его владелец, владелец директории или root**. Без него файл может удалить любой, у кого есть `w` на директорию.

Классический пример — `/tmp`: писать в неё могут все (`rwx` для «остальных»), но удалять чужие файлы никто не может. Для обычных (не sticky) директорий удаление чужого файла с `w`-правом на директорию — легально, что и является известной дырой в общей папке без sticky bit.

Символьное отображение:

| Символ | Означает | Без `x` на этой позиции |
| --- | --- | --- |
| `s` (владелец) | setuid + execute | `S` — setuid без execute |
| `s` (группа) | setgid + execute | `S` — setgid без execute |
| `t` (остальные) | sticky + execute | `T` — sticky без execute |

## Числовое представление прав (octal)

Каждое право кодируется битом: `r=4`, `w=2`, `x=1`. Права категории — сумма:

| Права | Сумма |
| --- | --- |
| `---` | 0 |
| `--x` | 1 |
| `-w-` | 2 |
| `-wx` | 3 |
| `r--` | 4 |
| `r-x` | 5 |
| `rw-` | 6 |
| `rwx` | 7 |

`-rwxr-xr--` = `754`. Специальные биты добавляются четвёртой цифрой: setuid=`4`, setgid=`2`, sticky=`1`. `/tmp` = `drwxrwxrwt` = `1777`, `/usr/bin/passwd` = `rwsr-xr-x` = `4755`.

## Как привилегии связаны с I/O и kernel mode

- Любая I/O-операция начинается с проверки прав в ядре — это часть стоимости syscall'а (п. 3).
- Спец-биты `s`/`t` — флаги в inode, и меняют поведение ядра при запуске программ и доступе к директориям (см. п. 12 про inode).
- `setuid` — главный механизм, позволяющий обычному пользователю «выполнить операцию от имени root», не получая весь shell root'а.
- Для Java-приложений это означает, что «недостаточно прав» — это ошибка уровня ядра, а не JVM: она лишь возвращает `AccessDeniedException`.

## Практика

```bash
# 1. Права в символьном виде
ls -l /usr/bin/passwd /tmp

# 2. Числовое представление прав (mode)
stat -c '%n %a' /usr/bin/passwd /tmp

# 3. setuid и sticky заметны прямо в ls -l
ls -l /usr/bin/sudo /usr/bin/passwd   # ищем rws
ls -ld /tmp                            # ищем rwt

# 4. Изменить права: u=rwx,g=rx,o= (750), установить setgid на директории
chmod 750 myfile
chmod 2750 mydir        # 2 = setgid
chmod 1777 mydir        # 1 = sticky bit, права как у /tmp

# 5. Что доступно процессу — реальные UID/GID
id
cat /proc/self/status | grep -E 'Uid|Gid'
```

Полезные вариации:

```bash
# Вывести только права числом
stat -c %a /etc/passwd

# Проверить спец-биты: есть ли 's'/'t'
ls -l /usr/bin/passwd | cut -c4
```

## Связь со следующими разделами

- Проверку прав выполняет ядро в kernel mode — механизм из п. 3.
- Права записаны в метаданных inode (п. 12), вместе с владельцем и группой.
- Права директорий влияют на доступ к «файлам» из п. 5: `x` на директории — это про вход, `r` — про просмотр имён.
