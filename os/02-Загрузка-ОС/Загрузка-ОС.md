# 2. Загрузка ОС

## Цепочка загрузки

Загрузка Linux проходит по цепочке:

```
BIOS/UEFI → Bootloader → Kernel → Init (systemd) → userspace
```

Каждый этап не «начинается заново» — он **подхватывает управление у предыдущего** и передаёт его следующему, как эстафетную палочку. Проследим эту передачу по шагам.

### BIOS/UEFI — как всё начинается

Всё начинается с включения питания. На материнской плате ещё нет ни одного бита ОС — работает **прошивка**: **BIOS** (Legacy) или современный **UEFI**.

- Прошивка проводит самопроверку оборудования (POST), инициализирует память, диски и периферию.
- **UEFI** — современная замена BIOS: поддерживает GPT, Secure Boot, загрузку напрямую с EFI-раздела (`/boot/efi`).
- Роль в I/O: это самый низкий слой — прошивка читает диск через собственные драйверы, без участия какой-либо ОС.

**Переход к Bootloader.** Прошивка — не операционная система, запускать ядро она не умеет. Её единственная задача — найти на диске маленькую программу-**загрузчик** и передать ей управление. Для BIOS это первый сектор диска (MBR), для UEFI — исполняемый файл на EFI-разделе (обычно GRUB2).

### Bootloader — разгон ядра

**Bootloader** (типичный представитель — **GRUB2**) подхватывает эстафету от прошивки.

- Считывает конфигурацию (`/boot/grub/grub.cfg`) и показывает меню выбора ядра или загружает ядро по умолчанию.
- Загружает в память ядро `vmlinuz` и образ **initramfs** — временную корневую ФС в памяти, содержащую модули драйверов, необходимые, чтобы смонтировать реальный корневой раздел.
- Передаёт ядру параметры командной строки (их потом видно в `/proc/cmdline`).

**Переход к ядру.** Загрузчик «разгоняет» ядро: закладывает его образ в память и прыгает в его стартовую точку. В этот момент управление впервые получает операционная система.

### Kernel — «под капотом» ещё до пользователя

Ядро распаковывается и начинает работать само. С этого момента всё происходящее отображается в журнале ядра — `dmesg`.

- Инициализирует подсистемы: управление памятью, планировщик, VFS, драйверы устройств.
- Выполняет **первые I/O-операции**: читает драйверы из initramfs, монтирует корневую ФС (`/`) — сначала read-only, затем перемонтирует её в read-write.
- При этом же формируются виртуальные ФС `/proc`, `/sys`, `/dev` — тема п. 11.

**Переход к Init.** Ядро готово, но пока в системе нет ни одного пользовательского процесса. Чтобы «ожить», userspace должен кто-то создать. Ядро создаёт **первый процесс — PID 1** — и тем самым передаёт управление ему.

### Init (systemd) — оживление userspace

**Init** получает от ядра управление и право запускать все остальные процессы. В современных дистрибутивах это **systemd**.

- Монтирует ФС из `/etc/fstab`, запускает сервисы, поднимает сеть.
- Подводит систему к целевому состоянию (`multi-user.target`, `graphical.target`).
- Каждый запущенный сервис — отдельный процесс, который systemd порождает из своего PID 1.

**Переход к userspace.** Когда systemd закончил поднимать сервисы, система полностью «ожила»: запущены демоны, сеть и входной экран. Дальше каждый процесс (ваш терминал, Java-приложение, сервис) живёт уже сам по себе.

### Userspace — рабочий режим

- Все приложения, сервисы и терминалы работают уже в user mode поверх ядра.
- I/O приложений обслуживается ядром через syscall'ы (подробнее в п. 3).

Итак, вся цепочка — это последовательная **передача управления**: прошивка находит загрузчик, загрузчик запускает ядро, ядро порождает PID 1, а PID 1 порождает весь остальной мир процессов.

## Почему это важно для понимания I/O

- Загрузка — это **первая демонстрация слоёв I/O**: прошивка → bootloader → ядро → userspace, и каждый слой работает со «своими» драйверами и ФС.
- Знание цепочки помогает диагностировать проблемы: медленный старт сервисов, зависание на этапе монтирования, ошибки драйверов в `dmesg`.
- Здесь же формируются виртуальные ФС `/proc`, `/sys`, `/dev`, к которым мы вернёмся в п. 11.

## Практика

Проверьте, как загружалась система прямо сейчас:

```bash
# Журнал ядра: инициализация устройств, драйверы, первые ошибки
dmesg

# Время старта каждого сервиса systemd по убыванию (кто "съел" загрузку)
systemd-analyze blame

# Общее время загрузки
systemd-analyze time

# Критическая цепочка загрузки — сервисы, которые стартуют последовательно
systemd-analyze critical-chain
```

Полезные команды для анализа этапов:

```bash
# Параметры, с которыми стартовало ядро
cat /proc/cmdline

# Какой корневой раздел смонтирован и какие ФС подключены
mount | head

# Текущий target (целевое состояние загрузки)
systemctl get-default
```

## Связь со следующими разделами

- Загрузка приводит к появлению user mode / kernel mode, в котором работает весь I/O (п. 3).
- systemd, запущенный на этапе Init, подробно разбирается в п. 13.
- Монтирование `/proc`, `/sys`, `/dev` — тема виртуальных ФС (п. 11).
