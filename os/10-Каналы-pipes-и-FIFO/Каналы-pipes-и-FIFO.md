# 10. Каналы (pipes) и FIFO

## Проблема: как передать данные между процессами

Процессы изолированы друг от друга (см. п. 3 — user mode, виртуальная память): один процесс не видит память другого. Но программы постоянно обмениваются данными: `ls | grep`, вывод одного сервиса в другой, журналы. Как передать данные, если адресные пространства разные?

Ответ — каналы (pipes): это механизм ядра, который соединяет вывод одного процесса со входом другого. Данные текут через **файловый дескриптор** (см. п. 6), а значит для каналов работают те же `read()`/`write()`, что и для файлов — ещё одно проявление концепции «всё — файл» из п. 5.

## Два вида каналов

| Вид | Имя в системе | Создание | Кто может подключиться |
| --- | --- | --- | --- |
| **Анонимный канал (pipe)** | нет имени, только в памяти | оператор `\|` в shell | только процесс-создатель и его потомки |
| **Именованный канал (FIFO)** | путь в файловой системе, например `/tmp/my_fifo` | `mkfifo` | любой процесс, у которого есть права на доступ |

Анонимный канал удобен для связки команд в shell, именованный — для связи независимых процессов и сервисов.

## 1. Анонимные каналы: оператор `|`

`ls | grep txt` запускает два процесса: `ls` и `grep`. Shell создаёт анонимный канал и подключает:

- `stdout` процесса `ls` → на конец канала (write-end),
- `stdin` процесса `grep` ← с начала канала (read-end).

```
┌─────────┐   write   ┌──────────────┐   read   ┌─────────┐
│   ls    │ ────────► │  pipe (ядро) │ ────────► │  grep   │
└─────────┘  stdout   └──────────────┘  stdin    └─────────┘
```

Под капотом shell вызывает `pipe()` — syscall, который возвращает **два дескриптора**: `fd[0]` (для чтения) и `fd[1]` (для записи). Затем `fork()` и переназначение дескрипторов через `dup2()` (см. п. 6 — перенаправление). В `strace` это выглядит так:

```
strace -f -e trace=pipe,dup2,close sh -c 'ls | grep txt'
```

Что важно понимать:

- Канал — это **буфер в ядре** (по умолчанию 64 КБ на Linux), а не на диске. Запись в переполненный канал блокирует писателя; чтение из пустого — блокирует читателя.
- Потоки данных в канале — это FIFO-очередь: прочитанное из канала исчезает, «перемотать» назад нельзя.
- Анонимный канал живёт, пока жив хоть один связанный с ним процесс. После смерти всех процессов он исчезает бесследно.

## 2. Именованные каналы: `mkfifo`

FIFO — тот же канал, но у него есть **имя в файловой системе**. Можно сделать «трубу» между двумя независимо запущенными процессами.

```bash
# терминал 1: создаём канал и ждём данные
mkfifo /tmp/my_fifo
cat /tmp/my_fifo          # блокируется, пока не появится писатель

# терминал 2: пишем в канал
echo "привет из другого процесса" > /tmp/my_fifo
```

После команды `cat` в первом терминале увидит "привет из другого процесса", и оба процесса завершатся.

Ключевые особенности FIFO:

- Создаётся как «файл» типа `p`. Проверить: `ls -l /tmp/my_fifo` → `prw-r--r--`.
- **Открытие FIFO блокируется**: `open()` для чтения не завершится, пока кто-то не откроет канал на запись (и наоборот). Пара процессов «встречается» через имя.
- После записи в канал данных в файле нет — это не файл на диске, а буфер в ядре. `du` покажет 0.
- FIFO удаляется командой `rm` — это обычная запись в директории.

## 3. Параллельное чтение и запись: почему это важно

Канал — это связь «много писателей → много читателей». Запись в канал атомарна, если её размер меньше 4 КБ (PIPE_BUF): данные из разных писателей не перемешиваются.

Классический приём — параллельные производитель и потребитель:

```bash
# генератор данных (бесконечный), пишет в FIFO
(while true; do date; sleep 1; done) > /tmp/my_fifo &

# потребитель (бесконечный), читает из FIFO
while read line; do echo "получено: $line"; done < /tmp/my_fifo &

# всё это два независимых процесса, обменивающихся данными через ядро
```

Если читателя нет, писатель блокируется на `write()` — канал полон или никого нет. Если писателя нет, читатель блокируется на `read()`. Это **естественная синхронизация** процессов: их скорости выравниваются автоматически, без семафоров.

Связанные с этим понятия (разберём в следующих разделах):

- Когда процесс читает из канала, он часто уходит в сон (state `S`) — это блокирующий I/O из п. 9.
- Если писатель закрыл канал, а читатель пытается читать дальше — `read()` вернёт 0 (EOF) и reader увидит конец данных.
- Разрыв канала (закрытие) читатель замечает как EOF; писатель при этом получает сигнал `SIGPIPE` (по умолчанию — завершение процесса, поэтому shell-конвейеры «обрываются»).

## 4. Общение между двумя терминалами через FIFO

Именованный канал — самый простой способ «соединить» два независимых терминала: процессам не нужно знать друг о друге, они встречаются через имя в файловой системе.

Разовое сообщение:

```bash
# терминал 1: создаём канал и слушаем
mkfifo /tmp/chat
cat /tmp/chat          # блокируется, пока не появится писатель

# терминал 2: отправляем одно сообщение
echo "привет" > /tmp/chat
```

Терминал 1 выведет «привет», после чего канал закрывается — FIFO передаёт данные один раз, повторного чтения из него нет.

Для непрерывного диалога — читатель в бесконечном цикле, писатель дописывает в канал каждую строку:

```bash
# терминал 1: читатель, работает постоянно
cat /tmp/chat

# терминал 2: писатель, каждая введённая строка уходит в канал
while read line; do echo "$line" > /tmp/chat; done
```

Здесь видна и автоматическая синхронизация: если терминал 1 не читает (канал заполнен), `echo` в терминале 2 блокируется, пока читатель не заберёт данные.

Ещё вариант — передавать не строки, а целый вывод команд:

```bash
# терминал 2: пишет в канал все последующие команды
script -f /tmp/chat

# терминал 1: видит вывод команд в реальном времени
cat /tmp/chat
```

После сеанса канал нужно удалить: `rm /tmp/chat`.

## Практика

```bash
# 1. Тип файла: канал или FIFO?
ls -l /tmp/my_fifo          # тип p — именованный канал
stat -c %F /tmp/my_fifo     # "fifo" (сравните с "regular file" в п. 5)

# 2. Создание FIFO
mkfifo /tmp/my_fifo
mkfifo -m 600 /tmp/my_fifo  # сразу задать права (доступ к каналу = доступ к данным)

# 3. Посмотреть, где в системе уже есть FIFO
find /tmp -type p 2>/dev/null
grep -r "" /proc/sys/kernel/pipe-max-size   # размер буфера канала в байтах

# 4. Увидеть syscall pipe() и dup2() под капотом
strace -f -e trace=pipe,dup2,close sh -c 'ls | grep txt'

# 5. Параллельные чтение и запись в одном терминале (для демонстрации)
mkfifo /tmp/demo
cat /tmp/demo &             # читатель уходит в фоновый режим и блокируется
echo hello > /tmp/demo      # писатель разблокирует читателя
```

Типичная картина: `cat /tmp/my_fifo` без писателя «зависает» — это нормально, процесс в состоянии `S` ждёт, пока кто-нибудь откроет канал на запись.

## Связь со следующими разделами

- Каналы — это дескрипторы из п. 6, поэтому над ними работают те же `read()`/`write()`, блокирующие и неблокирующие модели из п. 9.
- В `ls -l /proc/<pid>/fd` можно увидеть дескрипторы pipe (тип `pipe:[номер]`) — связь между п. 6 и п. 10.
- FIFO — это «файл» с типом `p` в файловой системе (п. 5 и п. 12), но данные живут в ядре, а не в inode.
- Далее — виртуальные файловые системы `/proc`, `/sys`, `/dev`, где «файлами» оказываются данные самого ядра.
