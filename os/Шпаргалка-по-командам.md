# Шпаргалка по Linux-командам (файловая система)

## 1. Типы файлов и метаданные (п. 5)

| Команда | Что делает |
| --- | --- |
| `ls -l /path` | показать тип и права файла (первый символ: `-` файл, `d` директория, `l` симлинк, `p` FIFO, `s` сокет, `b`/`c` устройство) |
| `ls -ld /dir` | показать информацию о самой директории, а не о её содержимом |
| `stat /path` | показать все метаданные файла: размер, права, владельца, inode, время изменения |
| `stat -c '%i %h %F' /path` | вывести только номер inode (`%i`), число ссылок (`%h`) и тип файла (`%F`) |
| `ls -li /path` | показать номер inode в первой колонке |

## 2. Файловые дескрипторы и стандартные потоки (п. 6)

| Команда | Что делает |
| --- | --- |
| `ls -l /proc/self/fd/` | показать открытые дескрипторы текущего процесса (0=stdin, 1=stdout, 2=stderr) |
| `ls -l /proc/1/fd/` | открытые дескрипторы процесса с PID 1 (systemd) |
| `echo "x" > file.txt` | перенаправить stdout в файл (перезаписать, `O_WRONLY\|O_CREAT\|O_TRUNC`) |
| `echo "x" >> file.txt` | дописать stdout в конец файла (`O_APPEND`) |
| `wc -l < file.txt` | читать stdin из файла |
| `cmd 2> err.log` | перенаправить только stderr в файл |
| `cmd 2>> err.log` | дописать stderr в файл |
| `cmd > out.txt 2>&1` | stdout в файл, затем stderr направить туда же (`dup2(1,2)`) |
| `cmd &> out.txt` | краткая запись: stdout + stderr в файл |
| `cmd &>> out.txt` | то же с дописыванием |
| `ls -la \| grep '^d'` | конвейер: stdout первой команды → stdin второй через анонимный пайп |
| `ls /nonexistent 2>&1 \| cat` | передать ошибки первой команды в конвейер |
| `exec > script.log 2>&1` | весь дальнейший вывод скрипта в файл |
| `exec 3> file.txt` | открыть файл как новый дескриптор 3 |
| `echo "text" >&3` | писать в дескриптор 3 |
| `exec 3>&-` | закрыть дескриптор 3 |
| `exec 3>&1` | сохранить текущий stdout в fd 3 (временная подмена) |
| `exec 1>&3` | вернуть stdout обратно из fd 3 |
| `command > /dev/null 2>&1` | отбросить весь вывод («чёрная дыра») |
| `echo "x" > /dev/fd/1` | обратиться к дескриптору через имя файла |
| `strace -f -e trace=dup2 bash -c 'ls > out.txt 2>&1'` | увидеть перенаправление как syscall `dup2()` |
| `ls -l /proc/$(pgrep -f 'java App')/fd/` | дескрипторы, которые держит Java-процесс |

## 3. Каналы (pipes) и FIFO (п. 10)

| Команда | Что делает |
| --- | --- |
| `mkfifo /tmp/my_fifo` | создать именованный канал (FIFO, тип `p`) |
| `mkfifo -m 600 /tmp/my_fifo` | создать FIFO с заданными правами |
| `cat /tmp/my_fifo` | читать из FIFO (блокируется, пока нет писателя) |
| `echo "msg" > /tmp/my_fifo` | писать в FIFO (блокируется, пока нет читателя) |
| `ls -l /tmp/my_fifo` | увидеть тип `p` (именованный канал) |
| `stat -c %F /tmp/my_fifo` | вывести тип: `fifo` |
| `find /tmp -type p` | найти в системе все FIFO |
| `cat /proc/sys/kernel/pipe-max-size` | размер буфера канала ядра в байтах |
| `strace -f -e trace=pipe,dup2,close sh -c 'ls \| grep txt'` | увидеть syscall'ы `pipe()` и `dup2()` под капотом конвейера |
| `rm /tmp/my_fifo` | удалить FIFO (обычная запись в директории) |

## 4. Виртуальные ФС: `/proc`, `/sys`, `/dev` (п. 11)

| Команда | Что делает |
| --- | --- |
| `df -h /proc /sys /dev` | показать, что это отдельные (виртуальные) ФС |
| `mount \| grep -E 'proc\|sysfs\|devtmpfs'` | увидеть, как смонтированы `/proc`, `/sys`, `/dev` |
| `cat /proc/self/io` | I/O-счётчики процесса: `rchar`/`wchar` (через read/write), `read_bytes`/`write_bytes` (реально на диск) |
| `cat /proc/self/fd/` | открытые дескрипторы процесса |
| `cat /proc/$$/status` | статус текущего шелла (PID, память) |
| `head -n 5 /proc/cpuinfo` | информация о CPU |
| `head -n 5 /proc/meminfo` | информация о памяти |
| `cat /proc/uptime` | время работы системы |
| `cat /proc/net/tcp` | сетевые соединения «как файл» |
| `cat /sys/class/net/eth0/address` | прочитать атрибут устройства (MAC-адрес) |
| `cat /sys/class/net/lo/operstate` | состояние интерфейса (up/down) |
| `echo 9000 > /sys/class/net/eth0/mtu` | изменить атрибут устройства (от root) |
| `ls -l /dev/sda /dev/null /dev/tty0` | увидеть типы узлов: `b` (block) и `c` (char) |
| `watch -n 1 'cat /proc/self/io'` | обновлять вывод раз в секунду |

## 5. Inode и ссылки (п. 12)

| Команда | Что делает |
| --- | --- |
| `stat /etc/hostname` | показать inode, число ссылок (Links), права, владельца |
| `ln original.txt hard_link.txt` | создать жёсткую ссылку (ещё одно имя того же inode) |
| `ln -s original.txt soft_link.txt` | создать символическую ссылку (отдельный файл с путём) |
| `ls -li a.txt b.txt c.txt` | сравнить номера inode: у hard-ссылок совпадают, у symlink свой |
| `stat -c '%i %h %n' file` | inode, число ссылок, имя файла |
| `stat -c '%h %n' /tmp` | число ссылок на директорию (≥2: `.` и `..`) |
| `rm original.txt` | уменьшить счётчик ссылок; данные живут, пока nlink>0 |
| `find /proc/self -maxdepth 1 -type l -ls` | найти симлинки в `/proc` (например, `exe`, `cwd`) |
| `strace -e openat cat soft_link.txt` | увидеть, как ядро открывает цель симлинка |

## 6. Сервисы systemd и файловая система (п. 13)

| Команда | Что делает |
| --- | --- |
| `systemctl cat sshd` | показать содержимое юнита и путь к файлу |
| `systemctl show sshd -p MainPID -p FragmentPath` | узнать PID сервиса и путь к его юниту |
| `journalctl -u nginx -f` | живые логи сервиса (перехваченные stdout/stderr) |
| `pgrep -a sshd` | найти процесс сервиса |
| `cat /proc/$(pgrep -x sshd \| head -1)/io` | I/O-счётчики сервиса как обычного процесса |
| `ls -l /proc/$(pgrep -x sshd \| head -1)/fd` | дескрипторы сервиса |
| `ls /usr/lib/systemd/system/*.target` | файлы targets (точек сбора загрузки) |
