# 7. Создание потоков в Java

## Зачем потоки в Java

Программа на Java часто должна делать несколько вещей «одновременно»: читать из сети и обновлять интерфейс, обрабатывать параллельно запросы на сервере, выполнять фоновые задачи. Для этого JVM даёт **потоки** (threads) — независимые линии выполнения внутри одного процесса.

Важно: потоки в Java — это **не абстракция только языка**. За каждым Java-потоком стоит реальный поток операционной системы (на уровне ядра — **LWP, Lightweight Process**). JVM просто оформляет его в удобный API.

## Потоки vs процессы (на уровне ОС)

| | Процесс | Поток (LWP) |
| --- | --- | --- |
| Что это | отдельная программа со своим адресным пространством | линия выполнения **внутри** процесса |
| Память | у каждого процесса своя (изолирована) | потоки **одного** процесса разделяют heap и код |
| Свой стек | да, у каждого процесса | у каждого потока **свой стек** и свои регистры |
| Таблица fd | своя у каждого процесса | общая у всех потоков процесса |
| Общение | IPC: pipes, сокеты, shared memory | напрямую через общую память (плюс объекты синхронизации) |
| Переключение | тяжелее (меняется адресное пространство) | легче (адресное пространство то же, см. п. 8) |

Ключевой вывод: потоки одного процесса **видят одни и те же объекты в куче** — поэтому им нужна синхронизация, но им не нужны механизмы IPC между процессами.

## Способы создать поток

### 1. Класс `Thread`

```java
class Worker extends Thread {
    @Override
    public void run() {
        System.out.println("Поток " + getName() + " работает");
    }
}

Worker t = new Worker();
t.start();   // запускает НОВЫЙ поток ОС
t.join();    // главный поток ждёт завершения
```

### 2. Интерфейс `Runnable` (предпочтительнее)

```java
Runnable task = () -> System.out.println("Задача в потоке");
Thread t = new Thread(task);
t.start();
t.join();
```

`Runnable` лучше, потому что отделяет **задачу** от **способа её выполнения** (тот же `Runnable` можно передать и в `ExecutorService`).

### 3. `ExecutorService` — пул потоков

Потоки создавать руками для каждой задачи дорого. Правильный способ — **пул потоков**:

```java
ExecutorService pool = Executors.newFixedThreadPool(4);

for (int i = 0; i < 20; i++) {
    final int n = i;
    pool.submit(() -> System.out.println("Задача " + n));
}

pool.shutdown();          // не принимаем новые задачи
pool.awaitTermination(5, TimeUnit.SECONDS); // ждём завершения
```

Пул создаёт потоки один раз и переиспользует их для многих задач. Внутри у `ExecutorService` — очередь задач (`LinkedBlockingQueue` и т.п.) и N воркеров, каждый в цикле берёт задачу из очереди и выполняет её `run()`.

## Что происходит при создании потока под капотом

Когда вы вызываете `t.start()`, происходят такие шаги:

```
Java-код:  t.start()
   │
   ▼
JVM (native): создаёт native-поток, вызывает pthread_create(...)
   │
   ▼
libc: pthread_create() делает системный вызов clone()
   │
   ▼
Ядро Linux: clone(CLONE_VM | CLONE_FS | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD, ...)
   │
   ▼
Появляется новый LWP — поток того же процесса
```

Разберём:

- **`pthread_create()`** — функция стандартной библиотеки POSIX-потоков (`libc`), с которой работает JVM как обычная C-программа.
- **`clone()`** — системный вызов Linux, создающий и процессы, и потоки. Разница — во **флагах**:
  - без флагов → новый **процесс** (своё адресное пространство, своя таблица fd);
  - `CLONE_VM | CLONE_THREAD | CLONE_FILES | ...` → новый **поток** (общая память, общая таблица fd, общий PID-группа, но свой стек и своё значение в регистрах).
- Флаги `CLONE_VM` и `CLONE_FILES` — это и есть то, почему потоки видят одну и ту же кучу и одни и те же дескрипторы (связь с п. 6: fd у потоков общие).

Посмотреть системный вызов на практике:

```bash
# следим за clone() при старте простой Java-программы с потоками
strace -f -e trace=clone,mmap java -cp . Main 2>&1 | grep clone | head -20
```

`strace -f` нужен, чтобы следить и за дочерними потоками тоже.

## Потоки и среда выполнения

- **Собственный стек у каждого потока**: JVM выделяет стек по умолчанию (`-Xss`, обычно 512 КБ – 1 МБ). Поэтому миллионы потоков сделать нельзя — упрётесь в память (стек + метаданные).
- **Thread Local Storage (TLS)**: у каждого потока свой участок памяти для локальных переменных потока — в Java это `ThreadLocal`.
- **Планирование**: потоком управляет планировщик ядра (в Linux — CFS), а не JVM. JVM просто передаёт поток ядру (подробнее — п. 8).

## Пример целиком

```java
import java.util.concurrent.*;

public class ThreadsDemo {

    public static void main(String[] args) throws Exception {
        // 1. Поток через Runnable
        Thread t = new Thread(() -> System.out.println("Поток из Runnable"));
        t.start();
        t.join();

        // 2. Пул потоков
        ExecutorService pool = Executors.newFixedThreadPool(4);
        for (int i = 0; i < 8; i++) {
            final int n = i;
            pool.submit(() -> System.out.println(
                "Задача " + n + " в потоке " + Thread.currentThread().getName()));
        }
        pool.shutdown();
        pool.awaitTermination(5, TimeUnit.SECONDS);

        System.out.println("Главный поток завершился");
    }
}
```

Ожидаемый вывод: задачи 0–7 выполняются в 4 потоках пула (`pool-1-thread-1..4`), причём порядок вывода недетерминирован — потоки планирует ОС.

## Практика

```bash
# 1. Сколько потоков у JVM реально живёт в ядре? (запустите пример выше и посмотрите)
jps                # найти pid JVM-процесса
ls /proc/<pid>/task/   # каждая директория = один поток (LWP) на уровне ядра

# 2. Посмотреть системный вызов создания потока
strace -f -e trace=clone java -cp . ThreadsDemo 2>&1 | grep clone | head -20

# 3. Сколько потоков создала JVM только для себя (GC, JIT, main)
ls /proc/$(pgrep -f ThreadsDemo | head -1)/task/ | wc -l
```

## Связь со следующими разделами

- Потоки создаются через `clone()` с флагами «общей памяти» — поэтому им нужна **синхронизация** (тема отдельного курса, здесь не разбирается).
- Переключение между потоками и планирование — п. 8: планировщик CFS, context switch, `/proc/<pid>/sched`.
